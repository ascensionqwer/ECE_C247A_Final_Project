\begin{abstract}
  We compare four neural network architectures: TDS Conv, GRU, LSTM, and CNN+RNN for predicting keystrokes from forearm sEMG signals using the emg2qwerty dataset and CTC loss. All models were trained on single-user 16-channel recordings across two hardware configurations. On Config. A (2$\times$RTX 3060), LSTM CTC achieves the best test CER of 15.99\% using 2$\times$ temporal downsampling (2 kHz $\to$ 1 kHz) across 11 unique configurations including electrode ablations. On Config. B (RTX 4080) at full 2 kHz sampling rate with matching configuration (batch=32, epochs=150), LSTM CTC also performs best at 18.59\%. Cross-platform evaluation confirms reproducibility: TDS Conv yields 22.28\% (Config. A) vs 21.79\% (Config. B), within 3\% relative difference. The best LSTM configuration uses full 16-channel input (1056 features), with performance degrading substantially when reducing electrode channels.
\end{abstract}


\section{Introduction}

Surface electromyography (sEMG) records electrical activity from muscles through skin-placed electrodes. Because finger and wrist movements activate distinguishable muscle groups in the forearm, sEMG is well-suited for typing detection.

Sivakumar et~al.\ \citep{sivakumar2024emg2qwertylargedatasetbaselines} introduced emg2qwerty, a dataset of 1,135 recording sessions spanning 108 users and 346 hours of 16-channel sEMG recordings with ground-truth keystrokes. The authors provided a Time-Delay Separable Convolution (TDS Conv) baseline trained with Connectionist Temporal Classification (CTC) loss, which handles alignment by marginalizing over all frame-to-character mappings.

Convolutional approaches like TDS Conv capture local temporal patterns, while recurrent architectures (LSTMs, GRUs) model longer-range dependencies. Which is better for sEMG decoding is not obvious.

We compare four architectures for sEMG-to-keystroke prediction: TDS Conv CTC, GRU CTC, LSTM CTC, and CNN+RNN CTC. All use CTC loss and are evaluated on single-user data. We report character error rate (CER) and error type breakdown, and run experiments on two hardware configurations: Config. A (2$\times$RTX 3060, 11 configurations including electrode ablations) and Config. B (RTX 4080, 4 architectures).

\section{Methods}

\subsection{Dataset}

We use the emg2qwerty dataset \citep{sivakumar2024emg2qwertylargedatasetbaselines}, which contains surface electromyography (sEMG) recordings from users touch typing on a QWERTY keyboard. The dataset comprises 1,135 recording sessions spanning 108 users and 346 hours of data. Each session includes 16-channel sEMG recordings from both left and right forearms, sampled at 2 kHz, along with ground-truth keystrokes captured via keylogger.

For this work, we train on a single user (\#89335547) for all methods. We use the default data splits: training sessions for optimization, validation sessions for hyperparameter tuning and early stopping, and test sessions for final evaluation. The sEMG signals come from two Delsys Trigno wireless electrodes per forearm, each with 8 channels (16 total per arm), placed over the flexor and extensor muscle groups. This ensures we maintain consistency across all methods, while not needing heavy compute requirements required by the full dataset.

\subsection{Preprocessing}

The raw sEMG signals are preprocessed in several steps. First, signals are converted from numpy structured arrays to PyTorch tensors, stacking left and right forearm channels along a band dimension to produce tensors of shape $(T, 2, 16)$, where $T$ is the temporal dimension, 2 represents the two forearm bands, and 16 is the number of electrode channels.

We compute log-scaled spectrograms using STFT with FFT size 64 (33 frequency bins) and hop length 16. This produces time-frequency representations of shape $(T, 2, 16, 33)$, computed independently per channel. The log transform ($\log_{10}(x + 10^{-6})$) compresses the dynamic range.

\paragraph{Configuration-Specific Preprocessing.} Most models use the full 2 kHz sampling rate without downsampling. As an experimental variation, two LSTM models on Config. A explore temporal downsampling: one uses $2\times$ downsampling (2 kHz $\to$ 1 kHz) and another uses $4\times$ downsampling (2 kHz $\to$ 500 Hz). All other Config. A models and all Config. B models use the full 2 kHz sampling rate.

During training, we augment with random band rotation (shifting electrode channels by $\{-1, 0, 1\}$ positions) to simulate electrode placement variability, temporal alignment jitter (up to 20 samples) between left and right forearm signals, and SpecAugment with time and frequency masking. The models receive 4-second windows (8000 samples at 2 kHz) with 900 ms of past context and 100 ms of future context padding.

\subsection{Model Architectures}

We compare four neural network architectures, all trained with CTC loss. They share a common frontend but use different temporal encoders.

\paragraph{TDS Conv CTC.} The baseline architecture uses Time-Delay Separable (TDS) convolutions for temporal modeling. The frontend consists of spectrogram normalization and a multi-band rotation-invariant MLP that processes each forearm band independently before flattening. The TDS encoder has 4 convolutional blocks with 24 channels each and kernel width 32, giving a temporal receptive field of 125 samples.

\paragraph{GRU CTC.} Replaces the TDS encoder with a bidirectional GRU. The shared frontend feeds into a GRU that processes the sequence in both directions, with dropout between layers.

\paragraph{LSTM CTC.} Same as GRU but with LSTM cells. The separate input, forget, and output gates give the LSTM more expressiveness than the GRU's two-gate design.

\paragraph{CNN+RNN CTC.} A hybrid: temporal convolutions extract local features after the frontend MLP, then a bidirectional GRU handles longer-range context.

All architectures conclude with a linear layer mapping to the character set (80 classes including letters, digits, punctuation, and special tokens) followed by log-softmax for CTC training.

\subsection{Training Setup}

All models use CTC loss \citep{graves2006connectionist}, which marginalizes over all valid frame-to-character alignments via a blank token and dynamic programming, avoiding the need for explicit alignment labels.

We use the Adam optimizer with a learning rate of $10^{-3}$, linear warmup over 10 epochs, and cosine annealing decay to $10^{-6}$. Batch size 32 fits within 12GB GPU memory while maintaining gradient stability. We train for up to 150 epochs with early stopping (patience 10) on validation loss. These settings were kept consistent across architectures for fair comparison. Our best test CER of 15.99\% improves 47\% over the baseline $\sim$30 CER from the project spec.

\subsection{Experimental Configurations}

We conduct experiments on two hardware configurations:

\textbf{Configuration A:} Batch size 32, maximum 150 epochs, trained on 2$\times$NVIDIA RTX 3060 GPUs (12GB each) via local Jupyter server.

\textbf{Configuration B:} Batch size 32, maximum 150 epochs, trained on a single NVIDIA RTX 4080 GPU.

For evaluation, we use character error rate (CER) computed via Levenshtein distance between predicted and ground-truth character sequences. We also report insertion error rate (IER), deletion error rate (DER), and substitution error rate (SER). Greedy decoding is used at test time for all experiments.

\section{Discussion}

\subsection{LSTM performance}

The best test CER we observe is 15.99\%, from an LSTM on Config. A with $2\times$ downsampling. This beats TDS Conv (22.28\%) and GRU (29.00\%) by wide margins, suggesting that LSTM's gating structure, with its explicit cell state, is a better fit for the temporal patterns in sEMG typing data.

That said, repeated runs of the same LSTM configuration produce CERs ranging from 15.99\% to 22.52\%, a spread of 6.53 points. The best run is something of an outlier; multiple restarts seem necessary to reliably get good LSTM results.

\subsection{GRU vs LSTM}

GRU consistently underperforms LSTM. On Config. A, LSTM reaches 15.99\% while GRU sits at 29.00\%. On Config. B with matching settings, LSTM gets 18.59\% versus GRU's 27.04\%. The gap is large enough that it is unlikely to be explained by initialization alone; GRU's simpler gating structure may genuinely lack capacity for this task. It is also possible that GRU needs different hyperparameters than what we tried; we did not tune per-architecture. The cross-configuration comparison is confounded by the preprocessing difference in the best Config. A run.

\subsection{Cross-platform variance}

TDS Conv gives 22.28\% on Config. A and 21.79\% on Config. B, a 0.49 point difference. Both use the full 2 kHz sampling rate. Given the different GPU architectures (Ampere vs Ada Lovelace) and random seeds, this level of agreement is reasonable and suggests TDS Conv results are reproducible across hardware.

GRU shows a larger gap (29.00\% vs 27.04\%), which may indicate it is more sensitive to initialization or subtle numerical differences between platforms. 

\subsection{Electrode channel importance}

Performance degrades roughly linearly as electrode channels are removed. The insertion error rate jumps from 2.81\% (16 channels) to 25.09\% (1 channel), meaning the model hallucinates many spurious characters when it lacks spatial resolution. Different finger movements produce muscle activations at different forearm locations, so fewer electrodes means less ability to distinguish between keys. Cheaper electrode arrays with fewer channels will pay a steep accuracy cost.

\subsection{Limitations}

Several caveats apply. First, the cross-configuration comparison confounds hardware, random seeds, and (for specific models) preprocessing, so we cannot isolate any single factor.

Second, two LSTM variants on Config. A use temporal downsampling (2$\times$ and 4$\times$), while Config. B uses the full 2 kHz rate. This makes direct cross-platform comparison unreliable when involving those downsampled runs.

Third, we did not tune hyperparameters per architecture. The GRU gap between Config. A (29.00\%) and Config. B (27.04\%) hints that results are sensitive to choices we did not explore systematically.

Fourth, all experiments use single-user data. Whether these architectural rankings hold for cross-user models is unknown.

Fifth, we only used greedy decoding. Beam search with language model rescoring would likely improve absolute numbers but was not tested due to lack of compute / time.

\subsection{Practical implications}

If accuracy is the priority, LSTM with full 16-channel input is the clear winner (15.99\% CER on Config. A with $2\times$ downsampling). The catch is high run-to-run variance; expect to train multiple times and pick the best.

For latency-sensitive or edge deployments, TDS Conv is a reasonable alternative at 22\% CER, with the advantage of a purely convolutional architecture that is straightforward to optimize for inference.

GRU, at 27 to 29\% CER, does not seem competitive under the hyperparameters we tested. Cross-configuration comparisons are complicated by the preprocessing differences noted above. We need further hyperparameter tweaking for GRU to be competitive.
